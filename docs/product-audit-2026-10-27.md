## 2026-10-28 第一批实施

已按本报告第一批顺序落实代码修复，版本号仍为 1.9.7，变更列入 CHANGELOG 的 Unreleased：

| 原问题 | 本批处理 |

| 文件目标随路径、主机或标签变化 | 地址草稿、显示目录和请求目录独立；任务固定 connectionId 与完整路径；缓存文件视图只处理自己的会话路由。 |

取消整个下载批次后，旧目录扫描即使稍后返回，也不能因新任务启动而重新入队；上传目录准备期间取消，会停止后续建目录和文件上传。

第一批最终验证：**535 项桌面测试全部通过**（原 487 项，新增 48 项）；桌面类型检查与正式前端、主进程和预加载构建通过。全仓 lint 为 0 错误、678 条警告。真实 Windows Electron 通过生产预加载访问隔离的本机 SSH/SFTP 服务，验证指纹确认与持久化、认证、PTY、命令输出、取消、文件上传下载及改名，未访问外部服务器。生产界面的隔离用户数据初始化及重启复核通过；该次使用隐藏窗口模式，未检查原生窗口激活和系统剪贴板。此次没有打包、发布、提交或推送。验证输出保存在被忽略的 `tmp/product-fixes/` 及 `tmp/windows-validation/`。

实现边界：每次新建或测试 SSH 连接会增加一次无凭据预握手；服务器离线后远端临时文件只能尽力清理；新下载使用本地硬链接完成不覆盖的提交，不支持此操作的存储需要选择其他目录。覆盖远端文件要求服务端支持安全替换，应用不会先删除原文件。

后续批次仍包含 AI 长输入与历史摘要、环境文档取消、无效 AI 设置，以及首次任务引导、模型工具就绪、导入去重、交互终端解码和更新等待。可选后端的令牌用途、刷新与撤销逻辑也尚未修复。下文保留分析当时的发现，不应将其全部视为当前未修复状态。

## 判断

Prism 已形成清楚的使用场景：独立开发者连接自己的服务器，在终端旁分析问题、巡检多台主机，并审核后续操作。SSH、SFTP、模型接入、多机分阶段执行和本机凭据保护已经具备基础。

下一版最值得投入的是让这条路径可靠：**连接正确服务器 → 保留用户要求 → 查看可信结果 → 确认具体操作 → 失败或停止后知道发生了什么**。当前发现的问题集中在目标身份、文件完整性、凭据出口、AI 上下文和取消语义。首次体验和国际化可以跟在这些修复之后。

本报告将确定缺陷与产品改进分开。优先级 P1 表示应在下一轮对外发布前优先修复；P2 表示随后完善。这里的优先级不代表已发生用户事故。

## 已有基础应保留

## P1：优先修复的确定问题

### 1. 文件操作目标可能跟随地址栏、目录或主机变化

地址输入直接修改 `currentPath`，列表成功加载后才更新 `displayedPath`，下载却按 `currentPath` 组成远端路径。仅编辑地址但不回车，仍显示旧目录文件时，点击下载就可能读取另一个目录的同名文件。

拖拽批量上传在处理每个文件时重新读取当前目录和连接。任务虽然记录了远端路径，执行时却没有统一使用该记录；隐藏的文件管理视图还监听全局路由变化。排队后切换目录或主机，后续文件可能被上传到另一处。

**受控复现：** 列表显示 `/srv/app/config.json`，地址输入改成 `/tmp` 后，下载提交 `/tmp/config.json`。另一个批量上传原定 `host-A:/original/`，执行首文件后改变当前状态，第二个文件实际发往 `host-B:/browsed-elsewhere/`。

依据：[地址输入](../apps/desktop/src/views/FileManagerView.vue#L68)、[下载路径](../apps/desktop/src/views/FileManagerView.vue#L1521)、[拖拽上传](../apps/desktop/src/views/FileManagerView.vue#L1384)、[全局路由监听](../apps/desktop/src/views/FileManagerView.vue#L2144)、[视图缓存](../apps/desktop/src/App.vue#L132)。删除操作已有 opaque identity 保护，不能据此认定删除也一定误删。

**修复方向：** 区分地址草稿、已显示目录和任务目标。入队时固定服务器 ID、远端绝对路径、本地路径；执行、重试和取消统一使用任务快照。缓存视图只处理自己的路由。

**验收：** 地址未提交、目录加载中、传输中切目录或主机、切标签后，所有任务都仍操作原定服务器和路径，记录与实际调用一致。

### 2. 文件传输中断可能破坏已有同名文件

普通上传和下载直接将最终路径交给 `fastPut` / `fastGet`，目标以写入模式打开，原文件可先被截断。断线、取消或磁盘满后，最终路径可能留下半文件。取消目前终结传输通道，没有恢复原文件的事务机制。

依据：[普通传输](../apps/desktop/electron/ipc/ssh-handlers.ts#L1274)、[传输结束与取消](../apps/desktop/electron/ipc/ssh-handlers.ts#L1231)。已核对当前安装的 ssh2 实现会以 `w` 打开目标；远端环境文档的临时替换防护尚未覆盖普通传输。

**修复方向：** 写入同目录临时文件，完成校验后再替换；先明确覆盖冲突，失败或取消清理临时文件。不同 SFTP 服务端的替换语义应分别处理，不能假定所有 rename 都能原子覆盖。

**验收：** 覆盖现有文件时分别模拟断线、取消和写盘失败，旧文件保持完整；成功后才替换，新建失败文件不会显示为完整成果。

### 3. 拖动连接节点会把解密后的凭据放入系统拖拽数据

拖拽处理直接将整个节点序列化到 `application/json`。连接树中包含解密后的密码、私钥配置和口令，文件夹还递归带有子连接。用户把节点拖到其他能接收这种数据的窗口，可能暴露凭据。数据库加密和 JSON 导出剥离无法阻止这个独立出口。

**受控复现：** 真实 `handleDragStart` 配合虚构连接，拖拽载荷包含 `password`、`privateKey`、`passphrase` 三个字段。

依据：[拖拽序列化](../apps/desktop/src/components/ssh/SSHTreeNode.vue#L543)、[连接树数据](../apps/desktop/electron/services/ssh-tree.service.ts#L299)。实际移动只需 [节点 ID 和类型](../apps/desktop/src/components/layout/AppSidebar.vue#L527)。

**修复方向：** 系统拖拽只放内部节点标识。进一步让连接列表只返回展示元数据，需要编辑或认证时再通过窄接口读取敏感值。

**验收：** 单个连接与多层文件夹的所有拖拽类型中都不存在凭据，内部移动和分组仍正常。

### 4. SSH 没有校验服务器身份

正式连接和测试连接共用的配置没有 `hostVerifier`，生产代码中也没有已信任指纹记录。ssh2 的[官方说明](https://github.com/mscdex/ssh2#client-methods)确认，未提供校验器时默认接受主机密钥。保存了服务器地址并不等于确认连接到原来的服务器。

依据：[连接配置](../apps/desktop/electron/ipc/ssh-handlers.ts#L69)。

**修复方向：** 首次连接展示 SHA256 指纹，经用户核对后保存；相同地址与端口的密钥发生变化时阻断认证，并提供明确的重置信任流程。测试连接使用相同规则。

**验收：** 拒绝未知指纹时不继续认证或保存信任；已信任服务器正常连接；替换密钥必被阻断；连接测试不能成为绕过入口。

### 5. AI 会丢失长输入和历史中的关键要求

当前转换对用户消息统一限制为 4,000 字符，只保留首尾，中间被静默移除。用户粘贴部署说明、Compose 文件或日志时，界面显示的原文可能与模型真正收到的内容不同。

历史压缩还有另一个问题：压缩函数生成 `system` 摘要，转换函数却只处理 user / assistant / tool，摘要没有进入请求。生产路径先压缩，再交给历史缓存；缓存仅保留助手和工具后缀，不能保护最新用户输入，也不能补回已压掉的摘要。

**受控复现：** 6,029 字符输入变成 3,629 字符，中段约束标记消失；首条与连续同模型的新输入都会发生。22 条历史压缩到保留 20 条后，摘要在中间结构中存在，但实际模型消息没有它；此前命中的旧助手缓存也被移除。

依据：[文字裁切](../apps/desktop/src/services/messages/convert.ts#L24)、[用户消息转换](../apps/desktop/src/services/messages/convert.ts#L125)、[摘要创建](../apps/desktop/src/services/messages/convert.ts#L277)、[生产调用顺序](../apps/desktop/src/components/chat/AIChatOpenCodeStyle.vue#L778)、[历史缓存范围](../apps/desktop/src/services/messages/processor-history.ts#L85)。

**修复方向：** 完整保留当前用户请求；容量不足时明确提示或分段。建立包含目标、用户约束、已执行事实、失败和待办的有效摘要，并保证它真正进入请求。摘要中的远端内容需要保留来源，不能被升级成可信系统指令。

**验收：** 将关键限制放在长文本中部，检查实际请求仍保留；跨压缩阈值、连续同模型及切模型后，既定约束和已执行结果都不会无声消失。

### 6. 停止环境文档任务后，仍可能继续发起写入

用户批准修改后，在远端读取尚未结束时点击停止，工具仍可能继续备份和修改。外层在整个更新工具返回后才检查 signal，文档工具的读取、备份、编辑步骤没有检查取消，文档 IPC 也没有对应的请求取消参数。

依据：[外层更新执行](../apps/desktop/src/services/tools/multi-host-tools.ts#L139)、[工具读取与修改](../apps/desktop/src/services/tools/ssh-tools.ts#L265)、[文档服务接口](../apps/desktop/src/services/doc-storage.service.ts#L66)。这是停止之后仍发起新写入的问题，不能仅用“已经发出的操作无法撤回”解释。

**修复方向：** 在每个异步步骤后及最终提交前检查取消，并将请求身份贯穿到主进程。保留现有临时文件替换；提交已完成后才收到停止，结果应明确显示已完成。

**验收：** 分别在读取中、备份中、临时写入后但提交前停止，禁止随后提交；已经提交的操作按真实结果呈现。

### 7. 部分 AI 设置与真实行为不一致

真实设置页提供并保存“自动批准只读操作”、命令风险等级、保存聊天历史及最大条数，但这些参数没有被现有聊天执行链消费。关闭自动批准后，专用读取工具仍直接执行；开启保存历史也没有相应的重启恢复。

依据：[设置控件](../apps/desktop/src/views/SettingsView.vue#L75)、[设置保存](../apps/desktop/src/views/SettingsView.vue#L1137)、[组件内消息](../apps/desktop/src/components/chat/AIChatOpenCodeStyle.vue#L188)、[会话服务只存配置](../apps/desktop/src/services/chat.service.ts#L14)。全生产源码引用检查未发现这四项进入执行或消息持久化流程。

**修复方向：** 接通有清楚语义的设置，或移除无效控件。关闭只读自动批准后，在读取可能传给模型的服务器内容前确认；写操作继续明确审核。历史功能需要有保存位置、保留期限、删除及重启恢复规则。

**验收：** 每个可见设置都能在重启后的实际行为中验证；关闭自动批准确实产生确认；开启历史后可恢复，关闭后的行为与说明一致。

## 可选服务端：启用账号与自托管代理时处理

这些问题属于可选后端，不影响桌面 SSH/SFTP 独立运行的事实；有对外账号服务时应与桌面 P1 同期处理。

### 令牌用途没有隔离，刷新后的用户字段也不完整

[登录](../packages/server/src/routes/auth.routes.ts#L98)用同一签名体系签发带 `type: refresh` 的长期令牌，[认证中间件](../packages/server/src/utils/auth.ts#L12)只验证签名，没有拒绝刷新令牌充当访问令牌。[刷新接口](../packages/server/src/routes/auth.routes.ts#L283)又从原本不含 username/role 的刷新令牌复制这些字段，导致新访问令牌缺失它们。刷新过程没有重新检查账号当前是否禁用；登出也没有撤销令牌。

**受控复现：** 使用实际路由及本地 Fastify/JWT、虚构用户，刷新令牌调用验证接口返回 HTTP 200；ADMIN 用户刷新后的访问令牌 role、username 均缺失。

**建议与验收：** 区分访问和刷新令牌用途，刷新时读取当前账号并重建必要声明，采用可撤销的刷新会话。刷新令牌访问普通受保护接口返回 401；停用账号及撤销会话不能再刷新。

### 登录密码会进入主进程请求日志

[请求摘要](../apps/desktop/electron/ipc/api-handlers.ts#L16)只特殊处理名字包含 token 的字段，其余字符串直接记录；[登录](../apps/desktop/electron/ipc/api-handlers.ts#L187)把含 password 的对象传入同一记录链。

**受控复现：** 虚构密码通过真实摘要函数后，完整值仍在日志对象中。实际是否持久保存取决于运行日志收集方式，但敏感值进入日志本身已经确定。

**建议与验收：** 对密码、密钥、认证头采用递归脱敏或字段白名单，避免 token 前缀记录。用虚构敏感值验证所有请求及异常日志均不出现原值。

### 健康检查可能把 Redis 不可用报告为整体正常

[健康路由](../packages/server/src/app.ts#L156)在 Redis 检查返回 false 时只将子字段标为 unhealthy，仍返回整体 healthy 和 HTTP 200。这会误导监控和部署验收。

**建议与验收：** 明确可用性和就绪条件；部署依赖 Redis 时不可用应返回非就绪状态。模拟 PostgreSQL 正常、Redis 失败，验证 HTTP 状态与整体状态一致。
