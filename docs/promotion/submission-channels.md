之前提到的 [AlternativeTo](https://alternativeto.net/faq/#add-a-new-application)仍可尝试：普通使用免费，需要账号和验证邮箱，官方说明普通审核可能等待数月。许可证、定价及与其他软件的替代关系应准确填写。

[Terminal Trove](https://terminaltrove.com/submit/)仍为条件候选：需要公开截图 URL、安装及平台信息。许可证字段允许 `unspecified`，但项目类型仅有 open source / open core / commercial；当前 Prism 授权方式尚未明确，不能擅自归入开源。其定位偏终端工具，GUI 工作台是否适合由编辑判断。

[Changelog News](https://changelog.com/news/submit)明确欢迎自荐，但不接受商业产品或服务，需账号；当前产品定价和授权分类未明确，暂不列为优先。

本轮未列为优先的渠道：SaaSHub 的[提交规则](https://www.saashub.com/services/submit)排除免费子域名；BetaList 的[当前帮助](https://betalist.com/help)说明投稿收费且要求自有域名；LinuxLinks 的[投稿说明](https://www.linuxlinks.com/faq/)关注自由及开源软件并审查许可证。当前 GitHub Pages 官网和未明确的项目许可证尚不满足这些渠道的优先投稿条件。

当前最便于沿用 GitHub 投稿流程的是第 1 项。第 2 项需要小众软件论坛账号，第 3 项需要明确发件邮箱，其余需要相应平台账号。现有平台账号、发信身份和发布范围明确后，再执行对外投稿。

小众软件对纯售卖内容和年费超过 100 元的产品有商业推广要求，详见[规则](https://meta.appinn.net/t/topic/43728)。模型服务费用应与桌面软件自身价格分开说明。该站对劣质 AI 内容也有明确限制，不直接复制已投周刊的稿件。

## 适合补齐条件后再投

### GitHubDaily 与 HelloGitHub

- [GitHubDaily](https://github.com/GitHubDaily/GitHubDaily) 的 README 明确接受通过 [Issue](https://github.com/GitHubDaily/GitHubDaily/issues/new) 推荐或自荐开源项目，涵盖开发工具和成熟应用。
- [HelloGitHub](https://github.com/521xueweihan/HelloGitHub) 的当前 README 将推荐与自荐指向[官网月刊页](https://hellogithub.com/periodical)，不要只按旧教程寻找 GitHub Issue 入口。

两者以开源项目为主要内容。当前工作区未见项目根许可证文件，因此建议维护者先明确项目授权方式，再准备此类开源自荐；不擅自填写 MIT 或把公开源码表述为已有明确开源授权。

### Terminal Trove

[官方提交页](https://terminaltrove.com/submit/)接受工具自荐，倾向跨平台、可安装的程序，必须提供预览图片，提交前须确认尚未收录。表单要求填写许可证、项目类型、平台与安装信息，也提供 SSH 等分类。

Prism 可以围绕终端和 SSH 工作台尝试推荐，但应明确是桌面应用，由编辑判断适配。表单有 `unspecified` 和专有许可选项，不应擅自选为开源。当前图片在本地工作区，表单需要可公开访问的图片地址，提交前应先准备好。可选 Express Lane 为 $199，首轮无需选择付费加急。

### AlternativeTo

[官方 FAQ 的添加应用说明](https://alternativeto.net/faq/#add-a-new-application)要求注册并验证邮箱，再从用户菜单建议新应用。适合按 SSH 客户端等实际用途获得长期检索入口，需要英文描述和准确的许可证信息。

普通队列可能等待较久；可选付费优先审核，价格在提交后展示，不保证通过。先明确项目许可证和英文介绍，不填未经确认的开源或定价类别。

## 下一轮准备

1. 先准备程序员版列表的短介绍，并确认尚无相同项目记录。
2. 为小众软件另写介绍，突出桌面体验、完整上手步骤与准确费用说明。
3. 准备英文用途介绍、下载入口和真实任务演示，供 Console.dev、DevTools Daily、DevHunt 使用。
4. 由维护者决定项目许可证，补齐后再考虑开源项目媒体及依赖许可证分类的目录。
5. 对外投稿后，才将实际链接与日期写入[渠道记录表](./channel-tracker.csv)；保持候选、投稿和收录状态的区别。
