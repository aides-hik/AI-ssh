# 棱镜 Prism 四周推广计划

本轮先验证自己管理少量 VPS 的开发者和自托管爱好者能否顺利使用产品。预算以现有仓库、视频和社区内容为主，不预设广告费用。

推广主入口使用现有 [产品官网](https://aides-hik.github.io/AI-ssh/)，同时提供 [Release 下载页](https://github.com/aides-hik/AI-ssh/releases/latest)。除非实际接入并核验统计，不将渠道参数当作已经具备的下载归因能力。

第 1 天指实际开始执行的日期。下表作为执行安排，当前已完成的材料和两份周刊投稿见[推广资料入口](./README.md)，不重复提交。阅读量、下载量和用户反馈从实际发布后开始记录，不引用旧博客计划中的业绩。

## 第一轮目标

- 争取 20 位目标用户实际安装并开始试用。
- 记录首次 SSH 连接、模型配置、一次 AI 任务完成或失败的主要原因。
- 完成至少 5 位用户的七日回访，争取其中 5 位仍在使用。未满七天的试用者暂不计入到期回访人数。
- 找到至少一个用户愿意重复使用的任务场景，以及两个值得继续投入的获客渠道。

这些是验证目标，不是增长预测。反馈由用户自愿提供，当前没有已完成数字。

## 第 1 周：准备入口，开始试用

| 时间 | 动作 | 交付与完成条件 |
| --- | --- | --- |
| 第 1 天 | 核对 README 首屏、下载和入门说明 | 普通用户能找到安装包，知道基础功能无需账号或后端，AI 需要自配模型 |
| 第 2 天 | 核对最新 Release 的平台附件与说明 | 记录实际可下载版本；新版本仍在构建时不宣传为已上线 |
| 第 3 天 | 制作主界面、多机巡检截图与短动图 | 文字可读，模拟界面附“界面预览，使用模拟数据”说明 |
| 第 4 天 | 使用测试服务器录制 75～90 秒操作视频 | 展示目标选择、巡检、命令确认与检查结果；素材符合演示脚本 |
| 第 5～6 天 | 由维护者向熟悉且有需求的人逐一邀请试用 | 使用邀请草稿，记录自愿反馈；不群发，不索要服务器凭据 |
| 第 7 天 | 汇总首次使用卡点 | 按安装、连接、模型、任务四类记录；优先处理阻止继续使用的问题 |

可以先从 5 位试用者开始，再逐步扩大到 20 位。若首次连接或模型配置持续失败，先修复对应问题，再扩大投放。

## 第 2 周：修复卡点，完成案例

| 时间 | 动作 | 交付与完成条件 |
| --- | --- | --- |
| 第 8～10 天 | 根据反馈修复最常见的阻碍 | README 或产品改动能覆盖具体问题；产品代码改动按仓库规范验证 |
| 第 11 天 | 整理一份真实任务案例 | 说明用户原本如何操作、使用 Prism 的过程和实际结果；取得公开案例所需同意 |
| 第 12 天 | 完善视频标题、简介与博客 | 从推广文案选用并核对，不写未经测量的提速倍数或使用人数 |
| 第 13～14 天 | 回访已满七天的首批试用者 | 记录是否继续使用、最常用场景、放弃原因和最需要的一项改进 |

真实案例优先采用“巡检几台测试服务器，定位资源或端口异常”。Compose 部署可以作为后续内容；展示前应在可恢复的测试环境完成整段操作。

## 第 3 周：分渠道发布并响应

| 时间 | 渠道 | 动作与记录 |
| --- | --- | --- |
| 第 15 天 | B 站 | 发布实操视频，简介提供下载与反馈入口；记录视频链接和发布日期 |
| 第 16 天 | 科技爱好者周刊 | 按仓库当前入口投稿，使用[投稿定稿](./weekly-submission.md)；可在截图已有公开链接后附图，记录投稿链接，收录状态单独记录 |
| 第 17 天 | 二丫讲梵学习周刊 | 重点介绍多机巡检场景，按当前投稿方式提交；记录实际链接 |
| 第 18 天 | 掘金或 CSDN | 先选自己已有账号的一处发布用户向教程，提供完整可复现步骤 |
| 第 19～21 天 | 已发布渠道 | 每天预留约 30 分钟处理问题，补充高频问答，记录来访者自报来源 |

渠道发布由相应账号持有人执行，或在明确渠道、身份和发布授权后执行。材料准备、投稿、收录和实际使用分别记录。

V2EX 作为可选渠道：作者先阅读 [站点规则](https://v2ex.com/about) 与 [节点说明](https://www.v2ex.com/help/node)，亲自写作开发经历。站点明确禁止 AI 生成内容，不直接粘贴本资料中的 AI 文案。可自行围绕“为什么做、一次真实使用、当前不足、希望得到什么反馈”书写。

## 第 4 周：比较效果，集中投入

| 时间 | 动作 | 完成条件 |
| --- | --- | --- |
| 第 22～24 天 | 回访已满七天的新增试用者 | 补足回访，并区分成功使用、继续使用、已放弃和未回复 |
| 第 25 天 | 汇总各渠道数据 | 来源不明的反馈单独记“未知”，不强行归因；缺失指标保持空白 |

## 统计口径

维护 [渠道记录表](./channel-tracker.csv)，只保存渠道汇总。用户原始反馈和可识别个人信息不放入公开仓库。

| 指标 | 记录方式 | 解释范围 |
| --- | --- | --- |
| 曝光量 | 使用平台实际提供的阅读或播放数，并在备注注明口径 | 各平台定义不同，不直接当作独立访客数 |
| 安装包下载次数 | 仅在有可靠来源时记录平台或 Release 附件下载统计 | 可能包含重复下载；无法按渠道识别的总下载量单独记录 |
| 自愿反馈成功使用人数 | 同一反馈者明确表示已连接自己的测试服务器并完成一次 AI 任务，人工去重 | 仅代表已回复样本，不是所有下载用户的转化率 |
| 七日回访人数 | 对首次试用满七天且实际回复的用户计数 | 未回复和未到期人数可写汇总备注 |
| 七日继续使用人数 | 到期回访中明确表示仍在使用的人数 | 按同一批回访样本比较；不将“计划继续用”计入 |

如用户只成功使用终端或 SFTP，记录在备注，保留该场景的价值，不归入完成 AI 任务人数。没有可靠的渠道级下载统计时留空，不用曝光量或点击量推算。

本轮不安装额外遥测，不收集 API Key、密码、私钥、完整终端日志或主机地址。公开统计前检查人数较小时是否可能反推出反馈者身份。

## 每周复盘四个问题

1. 用户能否按现有说明完成首次连接和模型配置？
2. 哪个任务让用户愿意再次打开 Prism？
3. 哪个渠道带来了成功使用者，花费了多少维护时间？
4. 下一周先改一个什么问题，或再验证一个什么场景？
